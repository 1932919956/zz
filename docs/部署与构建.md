# 部署与构建

## 一、直接部署（最终用户）

1. 从 **Releases** 下载 `AIROOM-v*-Windows-x64-Green.zip`，解压到不含中文和空格的目录（如 `D:\AIROOM`）。
2. 双击 `AIROOM.exe`。首次启动自动在 `%USERPROFILE%\.airoom\data` 建数据目录（聊天记录、密钥都在这里）。
3. 左下角「设置与连接」→「连接与版本」→ 添加连接，配置成员（详见 [使用说明](使用说明.md)）。

部署要点：

- `bridge\` 目录必须和主程序放在一起，否则 API 成员不可用。
- 不需要安装 Node / Python / 运行时；发行包里已经带齐。
- 程序常驻托盘，关窗口只是最小化。

## 二、从源码构建

前置条件：

| 依赖 | 版本 |
| --- | --- |
| Windows | 10 / 11 x64 |
| Node.js | 18 及以上 |
| npm | 随 Node 安装 |

步骤：

```powershell
git clone <官方 AIROOM 源码仓库>
cd <官方 AIROOM 源码仓库>

git apply ..\patches\源码改动补丁.patch
npm install
npm run build
```

构建产物在 `dist\`。把它覆盖到 `resources\app\dist` 即可看到效果，**不需要重新打包 exe**。

## 三、打安装包

打包使用 Electron 工具链（`electron-builder` / `electron-winstaller`，见 `app/package.json` 的 `allowScripts`）：

```powershell
npm run dist        # 生成免安装目录
npm run installer   # 生成安装包
```

产物在 `release\`（或 `dist\` 的同级输出目录），压缩成 zip 后即可作为 Green 版发布到 Releases。

## 四、运行时依赖

- `app/dist/runtime-dependencies.json` 记录了运行时依赖清单；
- `app/dist/verify-runtime-dependencies.ps1` 可校验依赖是否齐全：

```powershell
powershell -ExecutionPolicy Bypass -File app\dist\verify-runtime-dependencies.ps1
```

## 五、数据与权限

| 路径 | 内容 | 说明 |
| --- | --- | --- |
| `%USERPROFILE%\.airoom\data` | 聊天记录、设置 | 可备份 |
| `%USERPROFILE%\.airoom\data\electron` | 系统级加密密钥 | **禁止删除**，删了已存 Key 全部失效 |
| `bridge\api-keys.json` | 按服务地址存的 Key | 界面填不进去时的备用入口 |

- 成员默认拥有**全盘**文件权限；要限制到工位目录，设置 `API_TOOL_SCOPE=workspace`。
- 房间（项目会议室 / 茶歇室）内成员只读，不能改文件、不能执行命令。

## 六、常见问题

1. **API 成员显示未就绪**：检查 `bridge\api-acp.mjs` 路径、`API_BASE` / `API_KEY` 是否填对，改完要开新话题。
2. **密钥失效**：`%USERPROFILE%\.airoom\data\electron` 被删或换了用户目录，需要重新填 Key。
3. **界面白屏**：确认 `resources\app\dist` 完整（含 `renderer\` 子目录），或重新解压发行包。
4. **托盘图标不出现**：检查是否已有实例在运行（单实例限制）。
