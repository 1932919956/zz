# 这个分支和原版差在哪

> 对比对象：[tonyAmadeus/offAice](https://github.com/tonyAmadeus/offAice)
>
> 一句话总结：**原版负责"把多个 AI 组织起来"，这个分支补上了"让每个 AI 真的能干活"。**

---

## 一、最大的差别：多了 `bridge/` 这一层

原版里，每位成员的"能力"完全取决于它背后那个官方 CLI —— Claude Code 能读写文件，Codex 能跑命令，但**你换一个 API 接口进来，它只能聊天**。

这个分支加了 `bridge/`：

```
成员（任何 OpenAI 兼容接口）
   ↓ ACP（stdio + JSON-RPC）
bridge/api-acp.mjs        ← 适配器：把 HTTP 调用包装成 ACP 成员
   ↓ 工具循环
bridge/plugins/*.mjs      ← 插件：生图、搜索、记忆、派活
```

**结果**：不装任何客户端，只要一个接口地址 + 模型 ID，就能得到一个能读写文件、跑命令、生图的成员。

### 怎么用

```
设置与连接 → 添加连接 → 程序
程序路径：<仓库>/bridge/api-acp.mjs
环境变量：
  API_BASE=https://your-relay.example/v1
  API_KEY=sk-xxxx
  API_MODEL=your-model-id
  API_STYLE=chat
```

## 二、工具：从 0 到 18 个

原版没有"给成员加工具"这个概念。这个分支里，API 成员自带：

**内置 11 个**

| 工具 | 作用 |
| --- | --- |
| `read_file` / `write_file` / `edit_file` | 读写改文件 |
| `delete_file` / `move_file` | 删除 / 移动 |
| `list_dir` / `glob` / `grep` | 浏览、找文件、搜内容 |
| `run_command` | 跑命令 |
| `fetch_url` | 抓网页 |
| `update_plan` | 更新计划 |

**插件 7 个**

| 工具 | 作用 | 备注 |
| --- | --- | --- |
| `generate_image` | 文生图 | 30~70 秒/张，1536×1024 |
| **`edit_image`** | **图生图** | 给一张图 + 改法，返回新图 |
| `web_search` | 联网搜索 | Bing → 360 → 百度 三级回退 |
| `remember` / `recall` / `forget` | 跨会话记忆 | 存成文件，重启还在 |
| `ask_workbuddy` / `workbuddy_status` | 把活派给 WorkBuddy | 需要 WorkBuddy 在跑 |

**两个生图工具的区别**：

- `generate_image` —— **从零画**，输入是文字
- `edit_image` —— **在已有图上改**，输入是**图片路径 + 改法**（不需要模型有视觉能力）

## 三、工具能给别的运行时用（MCP）

原版没有。这个分支加了 `bridge/mcp-tools.mjs` —— 一个标准 MCP 服务：

```json
{
  "mcp": {
    "airoom-tools": {
      "type": "local",
      "command": ["node", "<仓库>/bridge/mcp-tools.mjs"],
      "enabled": true
    }
  }
}
```

**结果**：OpenCode、Claude Desktop、Cursor 这些支持 MCP 的运行时，都能用上这 7 个工具。

## 四、执行端目录：多了「免密钥」这条登录方式

原版的登录方式**全部要密钥**。这个分支加了：

```
OpenCode 免费模型（无需密钥）
```

选中它之后，AIROOM **不注入任何 provider 配置**，OpenCode 用它自带的免费模型（`glm-5.3-flash-free`、`deepseek-v4.1-flash-free` 等）。

**这个改动踩了五处坑**（都修了）：

| # | 位置 | 原来的问题 |
| --- | --- | --- |
| 1 | `renderer/executor-catalog.tsx` | 没填密钥 → 保存按钮禁用 |
| 2 | `renderer/executor-catalog.tsx` | 免密钥的登录方式还显示密钥输入框 |
| 3 | `backend/engine.ts` | 没密钥 → 判"不可用" → **选完自动切回上一个** |
| 4 | `backend/adapters/acp.ts` | `undefined.every()` 抛错 |
| 5 | `backend/executor-catalog.ts` | `secretKeys![0]` → **直接崩** |

**根因**：原版的整条链路都假设"登录方式一定有密钥"。

## 五、项目流程：方案里的负责人可以改

**原版**：负责人起草方案 → 你只能「确认」或「退回让它重写」。

**这个分支**：方案页每条任务旁边一个下拉框，**直接改谁做哪一条**，改完点「应用负责人」。

实现上新增了一个 RPC：

```ts
// 纯改数据，不调模型，瞬间生效
projectFlow.plan.retarget({ planId, expectedRevision, edits: [{ taskKey, memberId }] })
```

**为什么重要**：原来想换人只能"退回让 AI 重写一遍"，等 1~2 分钟，还可能改出别的东西。

## 六、文件上限放宽

| 项 | 原版 | 这个分支 |
| --- | --- | --- |
| 单文件 | 128 MB | **512 MB** |
| 总量 | 1 GB | **2 GB** |

涉及三个地方：`workspace.ts`（工作副本）、`workspace-checkpoint.ts`（还原点）、`project-flow-artifacts.ts`（成果清单）。

**注意**：每个任务副本都会复制一份项目，所以放 500 MB 的素材进去，24 个副本就是 12 GB。

## 七、交互上的几处修复

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| **Ctrl+C / Ctrl+V 失效** | `setMenuBarVisibility(false)` 会杀掉菜单快捷键 | 改成 `autoHideMenuBar: true`，另加编辑菜单 + 右键菜单 + 粘贴按钮 |
| **粘贴图片没反应** | 没有 `onPaste` 处理 | 加 `onPaste` + Ctrl+V 兜底 + 粘贴按钮 |
| **报告页打不开/误开** | 对非工作项目也尝试打开 | 加守卫 |

## 八、上下文压缩：不再把任务压丢

**原版适配器**的压缩是从 `messages[0]` 开始切的 —— 而**任务本体就在第 0 条**。

结果：成员读完几个大文件后，压缩触发，**任务描述被删掉**，成员下一轮回你：

> 当前消息未包含具体任务。请补充希望我基于这些文件完成什么。

**这个分支**：永远保留第一条用户消息，只压中间，尾部保留 8 条；摘要为空时也保留任务。

## 十、托管模式：把"等用户点"变成"自动跑"

**原版**：每个项目要你点 4 次 —— 确认方案、每轮验收、答决策卡、最后收尾。

**这个分支**：项目会议室右上角加了一个「⚡ 托管模式」开关。

### 它会自动做的

| 场景 | 动作 | 记录 |
| --- | --- | --- |
| 方案待确认 | 自动 `plan.confirm`，并把每轮 `requiresUserAcceptance` 设成 `false` | `✅ 自动确认方案第 N 版` |
| 轮次成品就绪（`integration.status === 'ready'` 且允许验收） | 自动 `round.accept` | `✅ 自动验收 第 N 轮「标题」` |

### 它**不**会做的

| 场景 | 为什么 |
| --- | --- |
| 决策卡（检查不通过 / 结果未知） | 方向性问题不代用户决定 |
| 任务失败 | 不盲目重试，避免烧额度 |
| 换人 / 改方案 | 同上 |

### 实现方式

**没有改后端** —— 是前端一个 1.2 秒的定时器，读快照判断状态，然后调**和按钮完全一样**的 RPC：

```ts
// 和 PlanCard 的「确认方案」按钮同一个调用
mutate('projectFlow.plan.confirm', {
  planId, expectedRevision,
  requiresUserAcceptanceByRound: { [每轮 key]: false },
})

// 和 RoundCard 的「通过」按钮同一个调用
decide(round, integration, 'pass')
```

**好处**：不需要在调度器里加钩子，失败也只影响这一个项目。
**代价**：依赖窗口开着（最小化可以，关掉不行）。

### 局限

- **最后一轮仍强制人工验收**（原版的 `isLast` 逻辑，没动）
- 决策卡仍然要人答 —— 这是设计上的取舍，不是没做完

---

## 十一、没改的部分

**下面这些是原版的，这个分支没动**：

- 四个房间（成员工位 / 茶歇室 / 项目会议室 / 圆桌）的设计
- 六步项目流程（讨论 → 定负责人 → 方案 → 执行 → 验收 → 完成）
- 人物卡、头像、性格系统
- 密钥的 DPAPI 加密存储
- 每任务独立工作副本的隔离机制
- 验收后才写回项目的流程

**这些本来就是原版做得好的地方，不该动。**
